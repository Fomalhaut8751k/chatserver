2. 2025.9.2
    修复了非聊天页面下收到聊天消息与其他消息的冲突

    
    ————当用户登录后，如果有其他用户发来消息，然后该用户去查看好友列表，这时recv会接收到好友发来的消息和服务器返回的好友列表的json串的合并，于是在反序列化的时候就会出错。也可能出现当用户登陆后，如果有其他用户发来消息，那么此时查看好友列表得到的可能什么都没有，即使他有好友，之后的查看或者刷新后就没有错。

    在gdb中复现错误情况：

    <img src="img/4.png" alt="图片描述" width="800" height="300">

    ————同时，由于原先分别为单人聊天和群聊设置了一个独立线程接收对应的聊天消息，会导致处在登陆状态，但没有处于聊天窗口时发送的消息无法及时接收到，因为没有对应的recv；不仅如此，在某个好友聊天页面可能出现其他好友发来的消息。

    为此，设计一个独立的消息接受线程，在用户登录后即开启，它包含唯一的recv，保证send和recv之间不会混乱。
    用户在登陆状态下，如果有人/群聊发来消息，且此时用户处在与该人/群聊的聊天页面上，就直接显示页面
    否则，就把消息存放到一个暂存的队列中，当打开对应的聊天页面时，这些消息就会优先显示出来。

    同时，针对json串可能合并的情况，通过循环将被合并接收的json串拆分开。
